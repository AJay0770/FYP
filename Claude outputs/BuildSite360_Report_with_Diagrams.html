1. Project Implementation Overview

BuildSite 360 is a comprehensive construction site monitoring platform designed to streamline operations, enhance safety compliance, and provide real-time visibility into project progress. The platform integrates AI-powered safety detection, biometric attendance tracking, real-time communication, and detailed site analytics into a cohesive system.

3. Architecture & Services

Monorepo Structure

BuildSite 360 is organized as a single Git repository containing three independent services:

client/ - React 18 frontend built with Vite. Uses Context API for state management (no Redux/Zustand). Communicates with backend via Axios with JWT interceptor and Socket.io for real-time updates.

server/ - Express.js API built with CommonJS. Manages 40+ REST endpoints nested by project ID. Integrates Prisma ORM, Socket.io for realtime events, AWS S3 integration, and FFmpeg for camera streaming.

ai-service/ - FastAPI microservice bound to localhost only (never exposed to browser). Implements YOLOv8s for PPE detection and DeepFace/ArcFace for facial recognition. Communicates with Node backend via X-Internal-Token authenticated endpoints.

Authentication Flow

JWT access tokens (24-hour expiry) + httpOnly refresh cookies (7-day expiry). Two-layer authorization: role check (ADMIN/ENGINEER/CLIENT) + project membership verification. Passwords hashed with bcrypt at cost factor 12.

4. System Architecture Diagram

This diagram illustrates how all system components interconnect and communicate. The React browser client communicates with Express.js API via REST endpoints. Socket.io handles real-time WebSocket events. The API interfaces with PostgreSQL database via Prisma ORM, and with the FastAPI AI service via internal authentication tokens. External services handle file storage (AWS S3), email delivery, PDF generation, and RTSP camera streaming.

5. Authentication & Authorization Flow

Two-layer authorization ensures data security. Users log in with credentials, receive JWT access tokens (24h) and refresh tokens via httpOnly cookies (7d). Every API request is validated for: (1) token validity, (2) user role (ADMIN/ENGINEER/CLIENT), (3) project membership. Unauthorized requests return 404 to prevent resource enumeration.

6. Safety Detection Workflow

The AI safety detection pipeline operates in real-time: RTSP camera streams are relayed via FFmpeg, analyzed by YOLOv8s model for PPE violations. When violations exceed the confidence threshold (0.75+) and are optionally matched to enrolled workers, SafetyAlert records are created and broadcast to all connected clients via Socket.io for immediate notification.

7. Attendance Tracking Workflow

Biometric attendance tracking eliminates manual timekeeping: Worker faces are detected by cameras, DeepFace/ArcFace extracts facial embeddings and compares against enrolled worker faces. Matches above the confidence threshold (0.60+) automatically create AttendanceRecord entries with a unique constraint per worker-date to prevent duplicates.

8. Report Generation Workflow

Automated daily and weekly report generation via node-cron: scheduled jobs query safety alerts, attendance records, material entries, and site updates from PostgreSQL. PDFKit aggregates this data into professional PDF reports uploaded to S3, with email notifications sent to stakeholders via Nodemailer.

9. Core Features Implemented

  • User & Project Management - Multi-role access control (ADMIN/ENGINEER/CLIENT) with project-level permissions, engineer assignment, budget tracking
  • Safety Monitoring & Alerts - Real-time PPE detection (helmets, vests) with confidence scoring and configurable thresholds
  • Biometric Attendance - Facial recognition enrollment, automatic check-in, match confidence scoring, daily records
  • Site Updates & Documentation - Engineer progress updates with media attachments, chronological site documentation
  • Material & Inventory - Receipt/consumption logging with per-unit costs, category tracking, project-based visibility
  • Real-time Communication - Project-scoped Socket.io chat, media sharing, message persistence
  • Analytics & Reporting - Daily/weekly automated PDF reports with safety metrics, attendance summaries, cost analytics
  • Multi-Camera System - Zone-based camera management (ENTRANCE/WORK_AREA/STORAGE), RTSP streaming, status tracking
  • Media & Asset Management - Centralized project media library with auto-recording from cameras and manual uploads
  • Payment & Subscriptions - Multi-provider support (EasyPaisa, JazzCash, Stripe), tiered plans (BASIC/PRO/ENTERPRISE)

10. Deployment & DevOps

Testing Infrastructure

Comprehensive E2E testing via Postman/Newman (40+ endpoints), Python integration tests for AI service, manual QA checklist. Database seeding via comprehensive seed scripts enables reproducible test environments.

Security Hardening

  • Two-layer authorization (role + project membership)
  • Fail-closed authentication design
  • X-Internal-Token for service boundary protection
  • Camera source validation before system calls
  • Webhook signature verification over raw request bodies
  • Biometric data handling with appropriate restrictions

Scalability Considerations

  • PostgreSQL connection pooling
  • S3 integration for unlimited file storage
  • Socket.io scalable to multiple server instances
  • FFmpeg process management for concurrent streams
